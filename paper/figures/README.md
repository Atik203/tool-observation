# `paper/figures/` — generated figures

Schematic figures for the ToolResult-800 manuscript. **Do not hand-edit the PNGs.** They are
generated by `paper/scripts/make_figures.py`; the script is the source of truth.

## Convention

| Property | Requirement |
|---|---|
| Format | PNG, opaque white background (alpha fully opaque) |
| Resolution | **600 DPI** (never below 600) |
| Base font | **16 pt** |
| Minimum text | **14 pt** |
| Axes / panel titles | **18–20 pt** |
| Figure titles | **22–26 pt** |
| Palette | Okabe–Ito colour-blind-safe palette |
| Layout | tight bounding box, 0.12 in padding |
| Backend | Matplotlib `Agg` |
| Content | schematics and conceptual shapes only; no fabricated results or data points |

The figures are deliberately large (roughly 15–18 in wide at 600 DPI) so the source text stays
above the 14 pt minimum and the files can be scaled for a full-width figure or slides. Font sizes
are set in the script, not by post-processing.

Dimensions are the values produced by the current script after tight-bbox cropping/padding.
They can change slightly if labels or layout change; re-run the verification after any edit.

## Regenerate and verify

From the repository root:

```powershell
C:\ProgramData\anaconda3\python.exe paper\scripts\make_figures.py
```

Check the existing files without redrawing:

```powershell
C:\ProgramData\anaconda3\python.exe paper\scripts\make_figures.py --verify-only
```

The verification step opens each PNG with Pillow, reads the DPI metadata, and fails if any file is
below 600 DPI or unexpectedly small. It prints the pixel dimensions and DPI for all four files.

PNG stores resolution as integer pixels per metre, so a 600 DPI file can report `599.9988` in
some readers (23622 px/m ÷ 39.3701). The script accepts anything at or above 599.5 DPI; the
rendered pixel dimensions are the authoritative check.

## Content rules

- **`fig-analysis.png` is explicitly illustrative.** Its axes are intentionally unnumbered, and
  the panels carry “illustrative, not data” in the titles plus an “ILLUSTRATIVE, NOT DATA”
  banner. It shows the *shape* of the conditional-logit model and a conceptual exponential
  recovery curve. It is not a result figure and must not be cited as evidence.
- **`fig-arms.png` uses a synthetic record** (flight `TA100`, a fabricated date and fare). It
  contains no real τ-bench observation and no PII. The values illustrate the manipulation, not
  study data.
- The only counts in `fig-design.png` and `fig-pipeline.png` are design constants from
  `README.md` and `docs/PROTOCOL.md` (800 primary prefixes, 400/400 domains, five arms, three
  models, the 34,800-generation envelope). They are not outcomes.
- When G3/G4 results exist, generate result figures from `artifacts/analysis/` (or the run
  ledger) and keep these four schematics as design figures. Do not add numbers to a schematic to
  turn it into a result figure. Every result figure must cite its ledger or manifest row.
